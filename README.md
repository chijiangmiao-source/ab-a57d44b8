# 星间链路 · 校验矩阵综合症复核

在网页录入至多 **32 行、40 列** 的 0/1 校验矩阵 `H` 与等长综合症 `s`，
发起复核后**精确**求解满足 `Hx = s` 的最小汉明重量二进制向量；重量相同时，
按列号顺序（第 1 列 → 第 40 列）比较位串，以 `0 < 1` 的字典序取唯一规范解。

- 不限制误码数、不随机尝试、不枚举全部 2^40 种组合；
- 目标不在列空间时显示“不可综合”，且不返回任何证据位串；
- 输入非法（行宽不一、非法字符、综合症长度不符）时原始草稿仍可编辑、
  错误可定位到行列、旧结论立即消失；
- 等待复核结果期间修改任一位，迟到的旧结果会被修订号（revision）机制丢弃，
  不会覆盖新草稿。

## 坐标约定（重要）

字符顺序即编号顺序：矩阵每个字符的列下标即列号（第 1 个字符为第 1 列），
综合症字符下标即行号（第 1 个字符为第 1 行）。解位串 `x` 与证据串同样按此
顺序给出，证据串恒等于所选列逐列异或、也恒等于输入综合症。

因此：

- 单位矩阵 + 综合症 `0010` ⇒ 唯一重量 1 解是**第 3 列**（`0010` 正是第 3 个
  单位向量；第 4 列是 `0001`），位串 `0010`，异或证据 `0010`；
- 两列均为 `11`、目标 `11` ⇒ 重量 1 解有位串 `10`（第 1 列）与 `01`
  （第 2 列），按 `0 < 1` 取 `01`，即**第 2 列**。

## 求解算法（`src/solver.js`）

1. 列以 BigInt 表示，先做 GF(2) 高斯消元：`s` 不在列空间则直接判不可综合；
2. 按重量 `w = 1, 2, …, rank` 逐层折半搜索（meet-in-the-middle，40 列在
   第 20 列处切分），首个可行重量即最小重量。单层组合数上界
   `C(20,10) ≈ 1.8×10^5`，远小于 2^40；
3. 每个异或值只保留位串字典序最小的选法，配对时先比左半再比右半，得到
   该重量下的规范解。

40×32 满秩随机矩阵实测 < 0.5 秒。

## 本地运行（无需安装依赖）

要求 Node.js ≥ 20。

```bash
npm start                 # 默认 0.0.0.0:8080
PORT=9090 npm start       # 自定义端口
```

- 页面：<http://localhost:8080/>
- 健康路径：<http://localhost:8080/health>（亦支持 `/healthz`）
- 复核接口：`POST /api/review`

## 测试 / 构建检查 / 冒烟

```bash
npm test      # 求解器（含 200 例与穷举交叉验证）+ HTTP API 测试
npm run build # 页面构建检查（文件、语法、资源引用、交互钩子）
npm run smoke # 健康路径与复核页面的 API/HTTP 冒烟（自动起临时服务）
```

## Docker Compose

```bash
HTTP_PORT=9090 docker compose up --build web      # 仅启动页面服务
docker compose up --build verify                  # 一次性验收
```

- `web`：Compose 启动的静态服务，提供 `/health` 健康路径与复核页面；
  宿主机端口由 `HTTP_PORT` 配置（默认 8080），带容器健康检查；
- `verify`：一次性验收服务，依赖 `web` 健康后启动，依次执行
  1. 最小误码与规范裁决的代码测试，
  2. 页面构建检查，
  3. 健康路径与复核页面的 API/HTTP 冒烟，

  执行完毕即退出，以退出码报告结果（0 成功，非 0 失败），`restart: "no"`。

## 目录结构

```
src/solver.js     精确最小重量 + 位串字典序裁决
src/parser.js     输入校验与行列级错误定位
src/server.js     零依赖静态服务 + POST /api/review
public/           复核页面（原生 HTML/CSS/JS，revision 防过期覆盖）
test/             node:test 单元与 HTTP 集成测试
scripts/          build-check / smoke / verify（一次性验收入口）
Dockerfile, docker-compose.yml
```
